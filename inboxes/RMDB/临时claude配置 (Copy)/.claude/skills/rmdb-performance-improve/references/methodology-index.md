# 寻性能突破点方法论库

性能探索的方法论不是唯一固定的——不同场景适合不同的方法。以下是一个**可积累的方法论库**，每次探索时可以从中选择一种或混合多种使用。

## 目录索引

| 方法 | 文件 | 适合场景 |
|------|------|----------|
| 特征驱动 | `characteristics-driven.md` | 从代码特性出发，系统性地找可省的开销 |
| 假设驱动 | `hypothesis-driven.md` | 有 profiling 数据，形成假设→验证的闭环 |
| 维度扫描 | `dimensional-scanning.md` | 需要灵感启发，按预定义清单逐一排查 |

通用理论见 `optimization-theory.md`，包含权衡分析、实战路径、总结清单。
RMDB 专项参考见 `rmdb-optimization-scope.md`，包含模块级性能债、TPC-C 负载特征、优化方案清单。

## 选择指南

当前处于**理论分析阶段**，无测试框架、无 profiling 数据。可用方法：

```
当前可用：
  ├── 读代码找浪费 → 特征驱动（characteristics-driven.md）
  ├── 系统扫描灵感 → 维度扫描（dimensional-scanning.md）
  └── 按模块排查 → rmdb-optimization-scope.md（性能债清单）

待测试框架就绪后启用：
  └── 假设驱动（hypothesis-driven.md）— 需要 profiling 数据形成闭环
```

三种方法不互斥：可以先用维度扫描或性能债清单找到候选方向，再用特征驱动分析具体开销。所有静态分析的结论标注"待实测验证"，测试框架到位后转入假设驱动闭环。
