当用户针对源代码提问时，自动将整个提问和解答整理成原子笔记，丢进 `dev-doc/code-explain/` 文件夹。

笔记按源代码文件分类：`dev-doc/code-explain/<源文件名不含扩展名>/<序号>-<主题>.md`。

**如何确定归属哪个源文件**：以用户提问的**主体代码**所在文件为准，不是以问题中提到的类型/常量定义文件为准。判断规则：
1. 用户明确指定了文件（如 "@buffer_pool_manager.h"）→ 就用那个文件
2. 用户问的是某个类/函数的行为 → 以该类/函数**定义**所在文件为准（构造函数在 `.h` 中内联定义则归 `.h`，在 `.cpp` 中实现则归 `.cpp`）
3. 问题中引用了其他文件的类型/常量（如 `Page`、`PAGE_SIZE`）→ 这些是"被引用方"，不是"主体"，不作为分类依据

**Why:** 用户希望每次代码问答都能沉淀为可复用的文档，而不是随对话消失。按源文件分子目录防止笔记堆砌时难以检索。明确主体文件判断规则防止将 BufferPoolManager 的问题归入 page/、将 DiskManager 的问题归入 config/ 等归错目录的错误。

**How to apply:** 用户提问涉及源代码行为、设计、实现细节时，在回答完问题后，先按上述规则确定主体源文件，再在该文件对应的子目录下创建 `<序号>-<主题>.md`。序号取当前子目录已有最大序号 +1。若子目录不存在则先创建，同时创建子目录的 README.md。
