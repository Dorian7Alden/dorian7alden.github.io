写测试代码时，默认不改动 `src/` 下的源代码。

**必须改时，三个前提缺一不可：**
1. 不影响源代码的功能
2. 不影响源代码的编译
3. 不引入新的问题

**除此之外，还必须：**
4. 先查 `git log` / `git blame` 确认问题是原始框架的还是后续引入的——如果原始框架能编译，说明问题出在开发过程，优先考虑能否在自己的测试代码内解决
5. 先向用户说明原因，获得明确允许后再动手

**Why:** 出题方提供的代码框架在没有明确允许的前提下禁止修改。最终要在线提交源码进行测试，改了源码可能导致线上测试对不上。测试代码是次要的，不能为了测试的便利反过来逼框架改头文件或修改源码结构。

**How to apply:**
- 测试文件需要访问内部类型 → 在测试文件中调整 `#include` 顺序（把缺失的头文件放在被测试的头文件之前），而不是给源码头文件补 include
- 测试需要访问私有成员 → 用 `#define private public` / `#undef private`，不改源码
- 源码有编译错误 → 先查 git 历史确认是不是原始框架的问题；即使真是框架问题也必须先问用户
- 不确定能不能改 → 问用户，别自己判断
- 测试 `planner.cpp` 中的自由函数（如 `pop_conds`、`push_conds`）→ 在测试文件中用前向声明
