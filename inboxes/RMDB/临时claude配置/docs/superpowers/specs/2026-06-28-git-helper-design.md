# git-helper 技能设计规格

## 概述

`git-helper` 是一个 Claude Code 斜杠命令技能，覆盖所有 git 相关操作（咨询、分析、命令执行）。核心原则：只读命令自动执行展示结果；写命令必须列出清单，经用户明确指向性确认后才执行。

## 触发方式

| 方式 | 触发条件 |
|------|----------|
| 手动触发 | 用户输入 `/git-helper <自然语言描述>` |
| 自动触发 | 用户做实施计划或讨论将要执行 git 操作时，技能自动激活进入分析模式 |

两种触发方式下，执行规则一致。

## 行为分层

### 第一层：只读命令（自动执行）

以下命令无需确认，直接执行并展示结果：

- `git status` — 工作区状态
- `git log`（含各种参数） — 提交历史
- `git diff`（含各种参数） — 差异对比
- `git branch` — 分支列表
- `git show` — 查看提交详情
- `git remote` — 远程仓库信息
- `git stash list` — 暂存列表
- 其他任何不修改仓库状态的安全命令

### 第二层：写命令（确认后执行）

流程如下：

1. **分析现状** — 执行必要的只读命令了解仓库状态
2. **生成命令清单** — 根据用户意图，列出所有待执行的 git 命令
3. **展示清单** — 清晰列出每个命令及其作用
4. **等待确认** — 用户必须给出明确指向性确认
5. **执行** — 按清单顺序执行，逐个反馈结果

## 确认规则（硬性门槛）

### 通过的确认（示例）

- "执行git操作"
- "执行这些git命令"
- "确定执行git命令"
- "执行git命令"
- "执行以上git操作"

共同特征：**明确包含"git"关键词 + 明确的执行意图**，指向性清楚。

### 不通过的确认（模糊，一律拒绝）

- "同意"
- "执行"
- "行吧"
- "好"
- "可以"
- "ok"
- "yes"
- "嗯"
- "对"
- 任何不含"git"关键词的确认

### 拒绝时的回应

反问用户明确其意图。示例回应：

> "你的确认不够明确，请指明是否要**执行以上git命令**。我只接受像'执行git操作'这样有明确指向性的确认。"

## 操作范围原则

**默认最小化：**

- 用户说"提交" → 只 commit，不 push
- 用户说"推送" → 只 push，不做其他
- 每个操作独立，不擅自扩大范围
- 如果分析后发现前置步骤必要（如先 add 才能 commit），将前置步骤一并列入清单并说明原因

## 技能结构

技能文件包含以下部分：

1. **触发条件说明** — 何时激活
2. **只读命令列表** — 可直接执行的命令
3. **确认流程** — 写命令的完整确认流程
4. **确认规则** — 什么是明确确认，什么是模糊确认
5. **操作范围原则** — 默认最小化
6. **示例交互** — 几个典型对话流程

## 示例交互

### 示例 1：只读查询

```
用户：/git-helper 看看当前仓库什么状态
技能：[自动执行 git status，展示结果]
技能：当前在 main 分支，工作区干净，没有未提交的更改。
```

### 示例 2：写操作，明确确认

```
用户：/git-helper 提交当前的改动
技能：[执行 git status, git diff 了解改动]
技能：当前有以下改动：
  - modified: src/app.ts
  - modified: src/utils.ts
建议执行以下命令：
  1. git add src/app.ts src/utils.ts
  2. git commit -m "update app and utils"
是否执行以上git命令？

用户：执行git操作
技能：[执行清单中的命令，逐个反馈结果]
技能：已完成：git add ... ✓，git commit ... ✓
```

### 示例 3：写操作，模糊确认被拒

```
用户：/git-helper 提交当前的改动
技能：[列出命令清单]
技能：是否执行以上git命令？

用户：好
技能：你的确认不够明确，请指明是否要**执行以上git命令**。我只接受像"执行git操作"这样有明确指向性的确认。

用户：执行git操作
技能：[执行清单中的命令]
```

### 示例 4：最小范围

```
用户：帮助我提交当前更改
技能：[分析改动，列出清单]
  1. git add <files>
  2. git commit -m "<message>"
（不包含 git push）
```

## 与其他技能的区分

`git-helper` 与 `commit-commands` 插件的关系：
- `commit-commands` 提供固定工作流（`/commit`、`/commit-push-pr`），是快捷命令
- `git-helper` 提供灵活的、对话式的 git 辅助，覆盖任意 git 操作，核心区别是确认门控
- 两者互补，不冲突
