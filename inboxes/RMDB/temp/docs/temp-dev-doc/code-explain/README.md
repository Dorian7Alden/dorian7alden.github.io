# code-explain

源代码解释文档，以"原子笔记"形式存放。每篇文档围绕一个具体问题的讲解，内容零散、独立，不成系统。

笔记按源代码文件分类：不同文件的讲解归入对应的子目录。

## 结构摘要

| 条目 | 用途 |
|------|------|
| `disk_manager/` | `src/storage/disk_manager.cpp` 的源代码讲解（10 篇） |
| `page/` | `src/storage/page.h` 的源代码讲解 |
| `buffer_pool_manager/` | `src/storage/buffer_pool_manager.h` 的源代码讲解 |

## 本层规则

**笔记按源代码文件分类，每个源文件对应一个子目录，目录名与源文件名（不含扩展名）一致。**
> **按文件分类的原因**：防止原子笔记过多时堆砌在同一目录下难以检索，按源文件分目录能快速定位到相关讲解。

**子目录内文件名格式：`<序号>-<主题>.md`，序号从 01 开始递增，两位数字。**
> **序号命名的原因**：原子笔记内容零散，没有固定的阅读顺序，用序号只作为标识和计数。

**每篇只讲一个问题，不延伸、不关联其他笔记。**
> **原子化的原因**：方便按需读取单篇，不必加载无关内容。跨笔记的关联通过各子目录 README 的结构摘要来维护。

**用户针对源代码提问时，AI 自动将问答整理成原子笔记，写入对应源文件的子目录，序号自动递增。**
> **自动沉淀的原因**：每次代码问答都应有文档产出，避免有价值的分析随对话消失。
