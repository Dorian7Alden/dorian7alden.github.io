Vue 的单文件组件（Single-File Component，简称 SFC）核心思想，可以用一句话概括：**将原本分离的 HTML 模板、JavaScript 逻辑和 CSS 样式，按照“高内聚”的原则，封装在同一个 `.vue` 文件中**。

这并非简单地将代码堆砌，而是一种旨在提升开发体验和项目可维护性的设计范式。

### 🧩 SFC 的基本结构

一个标准的 `.vue` 文件由三个顶级语言块构成：

*   **`<template>`**：定义组件的 HTML 结构。
*   **`<script>`**：包含组件的 JavaScript 逻辑，如数据、方法等。
*   **`<style>`**：定义组件的 CSS 样式。

### 🎯 SFC 思想的四大核心

1.  **关注点内聚，而非分离**：这是 SFC 最重要的思想。传统开发模式按技术类型（HTML/CSS/JS）分离文件，而 SFC 认为**一个组件的模板、逻辑和样式是紧密耦合、不可分割的**。将它们放在一起，能使组件更内聚、更易于维护。

2.  **组件即原子**：SFC 将每个组件视为一个独立的“原子单元”。这个 `.vue` 文件自包含、可复用，能被轻松地导入到项目的任何地方，非常利于模块化开发和代码共享。

3.  **约定优于配置**：`<template>`、`<script>` 和 `<style>` 的划分是一种框架层面的**约定**。这种清晰的规范让开发者（及 IDE）能快速理解组件结构，降低了团队协作和项目维护的成本。

4.  **开发体验优先**：SFC 的设计极大地优化了开发体验（DX）。它带来了**预编译模板**（性能更好）、**组件作用域的 CSS**（避免样式冲突）、**更好的 IDE 支持**（自动补全、类型检查）以及**模块热更新（HMR）**（修改代码即时生效）等特性。

### ⚙️ SFC 是如何工作的

SFC 是一种需要**构建工具（如 Vite 或 Webpack）** 支持的框架特定文件格式。浏览器无法直接运行 `.vue` 文件，它需要经过编译。

编译器（`@vue/compiler-sfc`）会将 SFC 转换为标准的 JavaScript 模块：
*   将 `<template>` 编译为**渲染函数**。
*   提取 `<style>` 并处理成 CSS。
*   最终，产出可直接在浏览器中运行的 JS 和 CSS 代码。

### 🤔 SFC 与传统方式的对比

| 维度         | 单文件组件 (SFC)                    | 传统分离方式                           |
| :----------- | :---------------------------------- | :------------------------------------- |
| **文件组织** | 一个组件 = 一个 `.vue` 文件         | 一个组件 = HTML + JS + CSS 等多个文件  |
| **关注点**   | **按功能（组件）内聚**              | **按技术类型（语言）分离**             |
| **维护性**   | 高，组件自包含，修改方便            | 低，需在多个文件间切换，依赖关系不清晰 |
| **样式隔离** | 原生支持（`scoped` 或 CSS Modules） | 需依赖命名约定或额外工具               |
| **开发体验** | 优秀，有热更新、类型检查等支持      | 一般，需手动刷新、检查                 |

Vue 的单文件组件思想，本质上是一种“**关注点内聚**”的哲学实践。它通过将相关的模板、逻辑和样式聚合在一起，让开发者能够更高效地构建和管理复杂的前端应用。
