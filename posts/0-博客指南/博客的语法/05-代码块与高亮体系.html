05-代码块与高亮体系 ​

代码块基于 Shiki 语法高亮引擎渲染，支持双主题自适应着色、自动折行、行号联动、行高亮与一键复制。

1. 核心特性 ​

  • 自动换行：代码超出容器边界时自动平滑折行，不产生横向滚动条，移动端自适应。
  • 行号联动：基于动态计数器实现，自动换行时行号精准对应代码起始行，不发生上下错位。
  • 一键复制：点击右上角复制按钮即可提取纯净代码，自动剥离行号及命令行首提示符，并在屏幕上方弹出全局固定提示。
  • 专有名词徽标：代码块右上角语言标识按业界标准专有名词大小写规范展示，例如 TypeScript、JavaScript、HTML、JSON、Bash 等，不再强制全部大写。
  • 代码折叠与展开：代码块默认全部展开，右上角配有折叠切换按钮，长代码段可随时收起，避免占用过多垂直阅读篇幅。点击折叠按钮或底部的折叠指示条即可重新展开。
  • 自定义内容标题：支持为代码块设置专属标题或文件名称，直观呈现代码所属的模块与文件路径。

6. 常见解析冲突与避坑指南 ​

在编写技术文档时，代码块如果与其他 Markdown 排版语法混用不当，极易触发解析冲突并破坏正文排版。以下总结了常见的高频冲突案例与避坑解决方案：

6.1 嵌套代码块提前闭合冲突 ​

当需要在外部代码块中展示另一段 Markdown 代码源码时，若外部与内部同时使用 3 个反引号，解析器扫描到内部的闭合反引号时会提前结束代码块，导致后续正文暴露损坏。

  • 解决方案：外部围栏代码块使用 4 个或更多反引号进行包裹，使外层定界符长度严格大于内层代码块；也可以使用波浪线 ~~~ 作为外层定界符进行交叉隔离。

6.2 列表内嵌套代码块序号中断冲突 ​

在有序列表或无序列表中插入代码块时，若代码块直接顶格书写或缩进不足，解析器会判定列表在此处已提前终结，导致紧随其后的后续序号被重置，破坏列表的连续性。

  • 解决方案：列表内部嵌入的代码块首尾围栏与内部每一行代码，均需统一缩进 4 个空格或与列表项正文缩进基准对齐，并在代码块前后各保留一个空行。

6.3 表格单元格内管道符冲突 ​

在表格单元格内使用行内代码展示含有管道符或逻辑或语法的语句时，例如 cat file \| grep text 或 a \|\| b，表格解析器会优先将未转义的竖线视为单元格列分隔符，导致整行表格列错位或裂解。

  • 解决方案：在表格单元格内部，行内代码中的竖线符号必须使用反斜杠转义，书写为 \|，或替换为 HTML 实体 &#124;。

6.4 引用块内嵌入代码块脱轨外溢 ​

在 > 引用块内部插入代码块时，若首尾围栏或中间代码行遗漏了 > 引导符，解析器会认为引用语境已提前结束，代码块将外溢到引用块外部，导致层级断裂。

6.5 首行四个空格意外触发旧式代码块 ​

传统 Markdown 规范将空行后缩进 4 个空格或一个 Tab 的纯文本定义为缩进代码块。在编写多级段落或粘贴内容时不慎缩进 4 个空格，会导致普通正文或列表被意外解析为无高亮、无样式的裸黑代码块。

  • 解决方案：全部统一使用三个反引号围栏代码块；普通正文段落首行不采用空格缩进，避免意外触发旧式缩进代码块。

6.6 行内代码包含反引号字符冲突 ​

行内代码若需要展示反引号字符本身，使用单个反引号包裹会导致定界符提前闭合。

  • 解决方案：外部使用连续双反引号包裹，并在内容首尾预留一个空格，解析器会自动剔除首尾辅助空格并完整保留内部的反引号。
