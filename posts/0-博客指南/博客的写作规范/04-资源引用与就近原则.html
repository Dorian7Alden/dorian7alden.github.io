04-资源引用与就近原则 ​

图片与静态资源是技术文档中重要的视觉论据。为了保证文档具备自包含性并防止全站资源目录混乱，博客制定了严格的资源存放与引用规范。

1. 本地插图就近原则 ​

在以往的静态博客维护中，常常存在将所有图片集中丢在全站根目录静态文件夹的现象，导致文档移动或重命名时图片链接大规模失效，且无法辨识某张废弃图片归属于哪一篇文章。

为此，博客全面贯彻同级收拢的就近原则：

  • 同级目录就近管理：某篇文章独占引用的本地截图、架构手稿与矢量插图，必须统一存放在该文档同级目录下的 assets/ 子目录中。
  • 相对路径引用：在 Markdown 中直接使用 ./assets/文件名.png 相对路径方式引用。
  • 自包含与高便携度：整个目录可被随时整体迁移、打包或备份，内部图片链接始终保持相对有效，杜绝全站散落碎片文件。

2. 在线图床与免 Referer 防盗链机制 ​

针对大型高清照片、公共图床或第三方对象存储托管的高频图片，支持直接引用标准在线 URL 链接：

  • 标准网络协议：使用完整的 https:// 链接直接插入。
  • 防盗链全局解决：很多公共图床与代码托管平台会对 HTTP 请求中的 Referer 来源进行严格校验，导致图片在个人独立博客域名下被拦截报 403 错误。博客在站点元数据与图片渲染插件中全局注入了 referrerpolicy="no-referrer" 策略，彻底解除防盗链拦截，确保图片顺畅加载。

3. 全站全局静态资源边界 ​

项目根目录下的 public/ 目录属于全站全局唯一资产目录，具备严格的归档边界：

  • 准入资产范围：仅允许存放全站共用的单例基础设施文件，例如 GitHub Pages 自定义域名映射配置文件 CNAME、浏览器标头图标 favicon.ico 等。
  • 严禁滥用：严禁将某篇单独博文的插图或临时演示文件丢入 public/ 目录中，防止公共根目录不断膨胀恶化。
