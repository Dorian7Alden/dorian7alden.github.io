01-核心定位与架构原则 ​

个人博客是知识结晶、技术思考与系统化沉淀的数字化载体。为了保持长期持续写作的低摩擦与高稳定性，系统在架构之初便确立了明确的技术定位与研发协同原则。

1. 系统定位与核心诉求 ​

在主流技术博客方案中，常见的选型往往在重量级动态系统如 WordPress、Ghost 与轻量级静态站点如 Hexo、Hugo、VitePress 之间权衡。

本博客选用 VitePress 作为核心引擎，深度结合 Vue 3 与 TypeScript，以满足技术博主的核心诉求：

  • 极速响应与现代化技术栈：基于 Vite 原生 ESM 驱动，本地写作热更新即时生效，毫秒级响应极大提升撰写心境。
  • 完全掌控的源码定制空间：不依赖黑盒插件生态，全站布局、主题样式、交互组件均以单文件组件方式透明维护。
  • 纯静态产物与零服务端运维：编译产物全部为纯静态 HTML、CSS 与客户端水合脚本，天然免疫服务端注入风险，具备极致的托管稳定性与访问性能。

2. 工作战场单一化与单分支模式 ​

工程维护中最消耗心智的往往是复杂的分支管理策略。为了杜绝上下文切换内耗，博客确立了工作战场单一化原则：

  • 全资产纳管于单一仓库：所有博客源代码、主题配置、辅助脚本以及全部博文笔记，统一放置于私有源码仓库内。
  • 坚决贯彻单分支 main 模式：不拆分所谓代码开发分支与内容创作分支，杜绝在不同分支间来回切换带来的合并冲突或工作区脏状态。
  • 阶段性变更自动持久化：遵循版本历史不丢失原则，完成阶段性修改、功能开发或文档调整后，应主动完成 Git 提交，及时固化工作成果。

3. 双仓库流水线与安全发布 ​

在代码资产保护与公开访问之间，博客构建了稳健的双仓库流水线解耦架构：

Mermaid
flowchart LR A[本地编辑与撰写] -->|git push origin main| B[私有仓库 blog-source] B -->|GitHub Actions 触发| C[远程环境自动化编译打包] C -->|静态产物推送| D[公开仓库 dorian7alden.github.io] D -->|GitHub Pages CDN| E[全球访客流畅浏览]

双仓库流水线的设计收益体现在三个维度：

  • 私有源码绝对安全：源码仓库保持私有属性，未完稿的草稿箱、自动化配置细节、私有笔记均不对外暴露。
  • 公开仓库仅含静态产物：目标公开仓库只接收 VitePress 编译生成的纯静态 HTML 文件，不包含任何敏感配置或源代码逻辑。
  • 全自动跨仓库部署流：通过在私有仓库配置 GitHub Personal Access Token，触发远程 CI/CD 自动化拉取、安装依赖、生产打包并强推至公开仓库，创作者本地无需执行繁琐的发布命令。

4. 协同规范与用户配置保护 ​

博主会随时根据个人偏好对排版边距、颜色变量、对齐微调等细节进行就地修改。在代码演进中，必须严格贯彻尊重用户手动调整的协作红线：

  • 严禁随意覆盖或重置：修改代码或优化组件时，必须仔细识别并保留用户已调整的样式数值与排版参数。
  • 协同适配优于推翻重来：遇到设计冲突或实现重叠时，主动融合适配已有改动，而非通过强制重置抹去个人心血。
  • 持续验证构建产物：任何改动完成后，均须通过本地开发服务与生产构建命令双重验证，确保构建零报错、页面无坏链。
