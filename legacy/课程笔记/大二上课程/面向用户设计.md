







## 二、核心概念定义


### 2.1 接口（Interface）
+ 定义：连接用户与系统的 “翻译器”，是用户与系统交互的软件载体，需同时满足前端用户需求与后端功能支撑。
+ 核心特性：建立有意义的用户 - 系统关系，而非单纯的技术展示。
+ 分类：
    - 应用接口（Application Interfaces）：独立运行，包含用户完成任务所需的全部功能。
    - 托管接口（Hosted Interfaces）：运行于浏览器等特定应用内，包含客户端接口与控制端接口两层。



### 2.2 交互（Interaction）
+ 定义：用户使用接口时的物理与认知行为总和，是用户与系统的双向对话。
+ 分类：
    - 物理交互：点击、输入、拖拽、滚动、手势、语音等具体操作。
    - 认知交互：决策交互对象、判断交互方式、解读系统反馈、处理界面信息等思维过程。



### 2.3 设计（Design）
+ 核心定义：“做正确的事”，是统筹元素以实现特定目标的规划过程（Charles Eames）。
+ 核心技能：综合约束条件合成解决方案、界定 / 重构问题、创造备选方案、可视化原型、选择最优路径。



### 2.4 可用性（Usability）
+ 定义：系统 “易于学习、易于使用” 的属性，直接关联工作效率与用户接受度，不等同于 “用户友好”。
+ 负面影响：设计不佳的界面会增加用户操作成本、导致误用 / 弃用、引发错误甚至故障。
+ 两大关键要素：
    - 可见性（Visibility）：交互控件可识别，且控件与效果存在清晰映射关系。
    - 可用性（Affordance）：控件外观需暗示其功能（如按钮暗示 “按压”），受用户背景与文化影响。



## 三、用户理解与分析


### 3.1 核心目标
设计师需理解用户的**真实需求**（而非表面表达）、工作方式与思维逻辑，识别用户多样性。



### 3.2 用户多样性维度
+ 认知能力：快速响应型 vs 深思熟虑型、逻辑导向型 vs 情感导向型。
+ 行为习惯：目标导向型 vs 探索型、果断型 vs 灵活调整型。
+ 背景差异：文化背景、技术熟练度、感官能力（视觉 / 听觉 / 触觉等）。



### 3.3 用户研究方法
+ 直接方法：访谈（Interviews）、问卷调查（Surveys）、现场观察（Observations）。
+ 间接方法：用户体验分析、理论与原则推导、历史数据复盘。



### 3.4 角色模型（Persona）
+ 定义：整合真实用户特征构建的 “虚拟用户”，用于精准定位用户需求与行为模式。
+ 核心要素：包含用户基本信息、技能水平、目标需求、使用场景、痛点与偏好，需搭配视觉形象增强记忆。
+ 分类：
    - 核心角色（Primary Personas）：系统的主要使用者，决定核心功能优先级。
    - 次要角色（Secondary Personas）：偶尔使用系统的用户，影响功能兼容性。
+ 优势：
    - 将抽象用户数据具象化，增强团队对用户的共情。
    - 为功能决策、交互设计、视觉设计提供统一依据。
    - 简化用户数据传递，便于跨团队协作。
+ 局限：
    - 与真实用户数据无明确对应关系，需通过用户测试验证。
    - 小型项目资源有限，难以深入开发。



## 四、用户认知与心理模型


### 4.1 感知（Perception）
+ 定义：用户通过感官接收系统信息并解读的过程，核心依赖视觉（占主导）、听觉、触觉等。
+ 视觉感知关键原则：
    - 视觉识别需满足 “物体可检测”（足够大小、对比度、可见色）与 “大脑可处理”（上下文匹配）。
    - 颜色感知：视网膜中心对颜色更敏感，蓝色辨识度低于红 / 绿色；约 8% 男性、1% 女性存在红绿色盲，需避免单独用红绿色传递关键信息。
    - 避免视觉错觉：如红蓝相邻产生距离错觉、斜线干扰导致水平线感知偏差。



### 4.2 认知（Cognition）
+ 定义：用户解读外部信息并指导行为的思维过程，核心关联记忆与信息处理。
+ 记忆系统特性：
    - 短时记忆：容量有限（7±2 个信息单元），需通过 “组块化”（Chunking）提升存储效率，如将长文本拆分归类。
    - 长时记忆：容量近乎无限，依赖重复使用与意义关联增强召回率，设计需提供记忆线索。
+ 认知负荷控制：通过简化界面、明确信息层级、减少无关信息，降低用户思维负担。



### 4.3 心理模型（Mental Models）
+ 定义：用户对系统工作原理的内在认知框架，影响用户对交互的预期与判断。
+ 核心作用：帮助用户描述系统、预测结果、查找问题原因、制定行动方案。
+ 特性：不完整、不稳定、无明确边界、非科学（可能包含迷信行为）、追求简洁。
+ 概念模型（Conceptual Models）：设计师与用户对系统的共同理解，是连接设计与用户心理的桥梁，需在设计前达成共识。



## 五、设计流程与方法论 The Design Process & Methods


### 5.1 传统设计模型局限
+ 瀑布模型（Waterfall Model）：线性流程（分析→设计→编码→测试→维护），聚焦技术视角，无迭代空间，难以匹配用户需求变化，不符合实际设计逻辑。



+ Waterfall model design limitation
    - Focus on technology
    - no interation
    - hard to match change
    - not match design logic
    - linearn design





### 5.2 UCD 核心设计模型：星型模型（Star Model）
+ 核心特点：以用户为中心，迭代式推进，各阶段成果持续反馈优化。
+ 关键阶段：
    1. 任务分析（Task Analysis）：明确用户需完成的功能及对应步骤，聚焦 “做什么” 而非 “怎么做”（如层级任务分析 HTA）。
    2. 需求收集与规范（Requirements Specification）：通过用户研究明确功能需求、用户目标、场景约束，输出需求文档（如用例图、客户旅程图）。
    3. 概念设计与形式设计（Conceptual/Formal Design）：确定设计理念、交互逻辑、界面布局。
    4. 原型设计（Prototyping）：构建可交互的初步版本，验证设计可行性。
    5. 实现（Implementation）：落地设计方案，开发功能完整的产品。
    6. 评估（Evaluation）：验证产品是否满足用户需求，识别问题并迭代。



### 5.3 原型设计（Prototyping）
+ 定义：快速构建的产品简化版本，用于测试设计思路与用户反馈。
+ 分类：
    - 水平原型：仅模拟界面，无实际功能。
    - 垂直原型：具备完整功能，但仅覆盖部分系统模块。
    - 全功能原型：功能完整，但性能可能受限。



### 5.4 UCD 设计方法论
| 方法名称 | 核心定义 | 优势 | 局限 |
| --- | --- | --- | --- |
| 快速情境设计（Rapid Contextual Design） | 现场观察 + 一对一访谈用户工作场景，结合建模、亲和图、故事板等输出设计 | 贴近真实工作流程，需求精准 | 需深入用户场景，成本较高 |
| 民族志观察（Ethnographic Observation） | 长期融入用户工作 / 生活环境，收集定量 + 定性数据 | 捕捉隐性需求与行为习惯 | 周期长，数据处理复杂 |
| 参与式设计（Participatory Design） | 让用户直接参与设计过程，影响决策 | 提升用户接受度，需求更贴合实际 | 可能延长周期、增加成本，需平衡用户建议与专业设计 |
| 敏捷可用性工程（Agile Usability Engineering） | 结合敏捷开发，短周期迭代，持续收集客户 / 用户反馈 | 快速响应需求变化，协作高效 | 需频繁沟通，对设计团队灵活性要求高 |




### 5.5 设计规则与指南
+ 标准（Standards）：由国际 / 国家机构制定（如 ISO 9241-11），基于稳定技术与理论，适用于硬件或软件基础设计。
+ 指南（Guidelines）：更通用的建议，分为抽象原则（设计初期）与详细风格指南（设计后期），如苹果 HIG、安卓 Material Design、Windows 设计原则。



## 六、交互设计 Interaction Design


### 6.1 交互核心流程
用户目标→形成意图→指定动作→执行操作→感知系统状态→解读结果→验证目标达成。

goal --> intention --> specifying --> executing --> perceiving --> interpreting --> evaluating

+ Forming the **goal**
+ Forming the **intention**
+ **Specifying** the action
+ **Executing** the action
+ **Perceiving** the state of the world
+ **Interpreting** the state of the world
+ **Evaluating** the outcome





### 6.2 交互范式 Interaction Paradigms
+ 定义：成功的交互模式可作为新系统设计的参考模型，依赖技术进步与用户认知习惯。
+ 关键范式：
    - 分时共享（Time-sharing）：从批处理转向交互式系统，支持实时交互。
    - 视频显示单元（Video-display units）：突破纸质信息展示，如 Sutherland’s Sketchpad。
    - 编程工具包（Programming toolkits）：提供模块化组件，降低复杂交互系统开发成本（如鼠标的发明）。
    - 个人计算（Personal computing）：小型专用设备，推动界面平民化。
    - 窗口系统（Windowing Systems）：基于 WIMP（Windows/Icons/Menus/Pointers），支持多任务并行。
    - 直接操作（Direct Manipulation）：对象可见、增量操作 + 快速反馈、支持撤销、动作替代语言（如拖拽文件）。



+ Key paradigms
    - **Time-Sharing**：batch systems to interactive systems
    - **Video-display units**：display information from paper to video
    - **Programming toolkits**：module components decrease dev cost
    - **Personal computing**：make interfaces easier to civils. specialized
    - **Windowing Systems**：multi tasks. WIMP (window, icons, menus, pointers)
    - **Direct Manipulation**：<font style="color:black;">visibility of objects, fast feedback, replace language with action</font>



### 6.3 交互风格 Interaction Styles
| 风格类型 | 定义 | 适用场景 | 示例 |
| --- | --- | --- | --- |
| 命令行界面（CLIs） | 通过命令指令操作，需记忆语法 | 重复性任务、技术熟练用户 | MS-DOS、UNIX |
| 菜单（Menus） | 展示可选操作，用户选择执行 | 功能明确、操作路径固定 | 软件菜单栏、手机设置菜单 |
| 问答式（Question/Answer） | 线性引导用户回答问题，逐步完成任务 | 流程固定的复杂操作 | 表单引导、安装向导 |
| 表单填充（Form fill-ins） | 结构化数据输入界面 | 数据录入场景 | 注册表单、信息提交界面 |
| 图形用户界面（GUIs） | 基于 WIMP，通过可视化控件交互 | 大众用户、多场景通用 | Windows/macOS 桌面应用 |
| 自然用户界面（NUIs） | 基于自然交互方式（触摸、手势、语音） | 移动设备、智能硬件 | 手机触屏操作、语音助手 |
| 自然语言（Natural Language） | 通过语音 / 文字对话交互 | 便捷查询、无界面场景 | 亚马逊 Alexa、 Siri |




### 6.4 <font style="color:rgb(6, 10, 38);">可用性设计原则 </font>Principles of Design for _Usability_
+ Provide a good **conceptual model**
+ Make things **visible** so that intuitive understanding can occur with ease
+ Take advantage of **natural** **mapping**
+ Provide **feedback**



### 6.5 可用性核心属性 attributes to _Usability_
| 属性名称 | 定义 | 关键影响因素 |
| --- | --- | --- |
| 可学习性（Learnability） | ease and speed to learn | 一致性、熟悉度、可预测性、可推广性 |
| 效率（Efficiency） | ease and efficiency after learn | 操作耗时、任务完成率、信息检索速度 |
| 灵活性（Flexibility） | exchange infos freely | 多线程处理、自定义配置、任务迁移 |
| 满意度（Satisfaction） | satisfaction from using | 美学设计、无冗余操作、情感共鸣 |
| 健壮性（Robustness） | fewer errors easily recover | 系统状态可见性、响应速度、错误恢复 |
| 可记忆性（Memorability) | no need to relearn to use | 视觉线索、简化记忆负荷、操作一致性 |




### 6.6 基本原则 basic principles
+ 简洁自然的对话：去除无关信息，按用户认知顺序组织内容。
+ 使用用户语言：避免专业术语，遵循现实世界惯例。
+ 最小化记忆负荷：通过可见控件减少回忆依赖，关键信息易获取。
+ 一致性：相同操作产生相同结果，遵循平台设计规范。
+ 提供反馈：实时告知用户操作结果，明确系统状态。
+ 明确退出路径：支持撤销、取消操作，避免 “迷路”。
+ 提供快捷方式：兼顾新手与专家用户，支持自定义常用操作。
+ 预防并友好处理错误：减少错误触发，错误提示明确且提供解决方案。



+ **Speak the user's language**
+ **Consistency**
+ **Feedback**
+ **Clearly marked exits**
+ **Shortcuts**
+ **Prevent errors**
+ **Error messages **



## 七、界面设计与可访问性 Interface Design & Accessibility Design


### 7.1 界面设计核心原则
界面设计需平衡**功能性与美学性**，核心原则包括：

+ 和谐（Harmony）：所有元素无缝融合，包括风格、尺寸、信息序列、反馈逻辑的一致性。
+ 平衡（Balance）：通过对称或不对称布局，实现界面元素的视觉均衡（如大小、方向、权重的平衡）。
+ 简洁（Simplicity）：并非 “朴素”，而是通过迭代设计实现清晰、优雅、高效的交互模型，避免冗余元素。



+ **Harmony**：the most important, fit seamlessly. style, size, feedback
+ **Balance**：arrangement, 	Symmetry and asymmetry
+ **Simplicity**：not plain, elegance, economy, clarity, interative achieved



### 7.2 界面设计实现方法
+ 优化（Refinement）：迭代测试，消除影响和谐、平衡、简洁的问题元素。
+ 克制（Restraint）：以最小元素实现核心功能，不盲目增加特性。
+ 统一（Unity）：通过统一尺寸、对齐方式、重复元素、合理留白建立视觉关联。
+ 模块化（Modularity）：将界面拆分为统一规格的模块（如设计网格），简化布局管理。



+ **Refinement**：eliminate problem elements
+ **Restraint**：Minimalist element, core functionality, avoid **unnecessary** features.
+ **Unity**：size, shape, align, repetition
+ **Modularity**：simplize layout management, design grids, group interface



### 7.3 可访问性设计（Accessibility）
+ 核心目标：实现 “全民可用”，覆盖永久、临时、情境性残疾用户（如视觉障碍、听觉障碍、运动障碍、认知障碍）。
+ 关键设计措施：
    - 颜色对比度达标，避免仅依赖颜色传递信息（适配色盲用户）。
    - 提供字体大小调整、屏幕阅读器支持（如 Alt 文本）。
    - 操作方式多样化（支持键盘、语音、手势等）。
    - 界面布局清晰、交互逻辑简单（适配认知障碍用户）。
+ 测试标准：遵循 W3C 的 Web 内容可访问性指南（WCAG），结合自动化工具与人工测试（如模拟障碍场景）。



+ Actions
    - Personas
    - Colour contrast
    - Fonts, typefaces and spacing
    - Alt text
    - Screen readers
    - …just to name a few



## 八、界面评估方法


### 8.1 评估核心目标
+ 验证产品功能是否符合用户需求。
+ 识别界面的可用性问题与改进空间。
+ 对比不同设计方案的优劣。
+ 收集量化与质化数据，支撑设计迭代。



### 8.2 评估分类与方法


#### 8.2.1 按评估场景分类
| 评估类型 | 核心特点 | 方法示例 |
| --- | --- | --- |
| 自然主义评估（Naturalistic Evaluation） | 真实场景观察，外部有效性高 | 直接观察、间接观察、用户访谈、问卷、情境查询 |
| 实验评估（Experimental Evaluation） | 控制变量，内部有效性高 | 对照实验、任务绩效测试、用户偏好对比 |




#### 8.2.2 关键评估方法
+ 认知走查（Cognitive Walkthroughs）：基于原型、任务清单、用户画像，模拟用户操作流程识别问题。
+ 启发式评估（Heuristic Evaluation）：核心评估方法，由 3-5 名专家依据可用性原则审查界面。
+ 核心原则（Saul Greenberg）：	
    1. 简洁自然的对话：匹配用户任务序列，聚类相关信息。
    2. 使用用户语言：避免技术术语，反馈清晰。
    3. 最小化记忆负荷：依赖识别而非回忆。
    4. 一致性：操作、语言、图形效果保持统一。
    5. 提供反馈：实时告知操作结果，明确延迟时间（<0.1s 即时，1s 可接受，>10s 需提示）。
    6. 明确退出路径：支持取消、撤销、退出操作。
    7. 提供快捷方式：适配不同熟练度用户。
    8. 积极处理错误：区分失误（Slips）与错误（Mistakes），提示明确且无指责性。
+ 优势：低成本、快速、适用于设计各阶段（纸质原型→成品）。
+ 局限：需专家经验，无法完全替代用户测试。
+ 用户测试（User Testing）：招募目标用户完成真实任务，收集操作数据与主观反馈，核心价值：“测试 1 名用户优于不测试”。



### 8.3 评估伦理要求
+ 尊重用户：避免造成压力或不适，保障隐私与数据安全。
+ 透明沟通：明确告知测试目的、流程，获取用户 consent。
+ 合理使用数据：匿名化处理，规范存储与销毁流程。
+ 避免 “黑暗模式”（Dark UX）：不设计误导、强迫用户的交互。



## 九、关键人物与经典理论


### 9.1 唐纳德・诺曼（Donald Norman）
+ UCD 领域核心学者，提出 “可用性” 核心概念与心理模型理论。
+ 关键贡献：强调 “以用户认知为中心”，指出设计需补偿人类记忆、感知局限，代表作《设计心理学》。



### 9.2 核心理论支撑
+ 生态感知理论（Ecological Perception Theory）：控件的可用性需匹配用户对现实世界物体的认知。
+ 认知负荷理论（Cognitive Load Theory）：界面设计需控制信息复杂度，避免超出用户处理能力。

特点：能够直观地展示产品的最终形态和交互细节，为用户提供更真实的体验，有助于发现设计中的

    提供详细的设计参考。例如，在电商APP的设计基本确定后，制作高保真原型，展示
    商品图片、价格、详情介绍等详细信息，以及商品的添加到购物车、结算等交互效果，
    让用户提前感受产品的实际使用体验。</code></pre><pre data-language="cpp" id="rSNcZ" class="ne-codeblock language-cpp"><code>定义：垂直原型也称为部分功能原型，它专注于实现产品的某一个或几个核心功能，
    深入展示这些功能的详细流程和交互逻辑，而不涉及产品的所有功能。

特点：能够深入验证产品的核心功能和业务流程，帮助团队更好地理解和优化这些关键部分。
    但它只覆盖了产品的部分功能，不能全面展示产品的整体架构和功能体系。

适用场景：当产品的核心功能较为复杂，需要重点验证和优化时，使用垂直原型进行深入测试和改进。
    例如，对于一个社交APP，先制作一个垂直原型，专注于实现用户的注册、登录、
    发布动态和查看动态等核心功能，通过对这些功能的测试和优化，确保产品的核心业务
    流程的顺畅性和易用性。</code></pre><pre data-language="cpp" id="HuFn7" class="ne-codeblock language-cpp"><code>定义：水平原型也称为全功能原型，它涵盖了产品的所有主要功能模块，

    以及各功能模块之间的交互关系。

特点：能够全面展示产品的整体功能和架构，让用户对产品有一个整体的认识，
    有助于评估产品的功能完整性和流程合理性。但由于每个功能模块的实现不够深入，
    可能无法详细展示某些复杂功能的具体操作和效果。

    让团队成员和利益相关者对产品的全貌有一个清晰的了解；或者在产品的需求调研阶段，
    用于收集用户对产品功能和流程的反馈。例如，在设计一个在线教育平台时，
    制作一个水平原型，展示课程列表、课程详情、学习记录、考试系统等所有主要功能模块的
    界面和跳转关系，让用户对平台的整体功能有一个初步的认识。</code></pre><pre data-language="cpp" id="fmLcK" class="ne-codeblock language-cpp"><code>定义：静态原型是一种没有交互功能或只有简单交互效果（如页面跳转）的原型，
    主要通过静态页面展示产品的设计和布局。

特点：制作简单、快速，能够直观地展示产品的界面设计和内容排版。但它无法让用户
    体验到产品的真实交互过程，对于一些需要通过交互来实现的功能和效果难以展示</code></pre></details>


<details class="lake-collapse"><summary id="uafb9393f"><span class="ne-text">评估步骤（Evaluation Steps）</span></summary><p id="u65a36ae6" class="ne-p"><br></p><p id="u86147ef7" class="ne-p"><span class="ne-text">精简背诵版：</span></p><p id="u822e9d25" class="ne-p"><code class="ne-code"><span class="ne-text">Select -&gt; Train -&gt; conduct -&gt; analyze -&gt; report</span></code></p><ol class="ne-ol"><li id="uff93606b" data-lake-index-type="0"><strong><span class="ne-text">Select Evaluators：</span></strong><span class="ne-text">3-5 Experienced Evaluators</span></li><li id="uaad3475e" data-lake-index-type="0"><strong><span class="ne-text">Train Evaluators：</span></strong><span class="ne-text">familiar with</span><strong><span class="ne-text"> </span></strong><span class="ne-text">Heuristic Principles, Evaluation Process、methods</span></li><li id="u90180284" data-lake-index-type="0"><strong><span class="ne-text">Conduct Evaluation：</span></strong><span class="ne-text">Independent Interface check,record problems</span></li><li id="u01b8ba8c" data-lake-index-type="0"><strong><span class="ne-text">Consolidate &amp; Analyze Issues：</span></strong><span class="ne-text">Remove Duplicates, Categorization, Analysis</span></li><li id="u8c5fc78b" data-lake-index-type="0"><strong><span class="ne-text">Report Results：</span></strong><span class="ne-text">Evaluation Report, Improvement Suggestions</span></li></ol><p id="uc440b650" class="ne-p"><br></p><p id="u1c3f7cbb" class="ne-p"><span class="ne-text">评估步骤</span></p><ol class="ne-ol"><li id="ubbaa29ab" data-lake-index-type="0"><span class="ne-text">选择评估人员：通常选择3 - 5名具有相关经验的评估人员，他们可以是设计师、开发人员、用户体验专家等。</span></li><li id="u74b6d8a2" data-lake-index-type="0"><span class="ne-text">培训评估人员：让评估人员熟悉启发式原则和评估的流程、方法。</span></li><li id="u712b1afc" data-lake-index-type="0"><span class="ne-text">进行评估：评估人员独立对界面进行检查，依据启发式原则找出存在的可用性问题，并记录问题的描述、严重程度、违反的原则等信息。</span></li><li id="ub0ccefcf" data-lake-index-type="0"><span class="ne-text">汇总和分析问题：将所有评估人员发现的问题进行汇总，去除重复的问题，并对问题进行分类和分析。</span></li><li id="u7512a3aa" data-lake-index-type="0"><span class="ne-text">报告结果：将评估结果整理成报告，向相关人员（如产品经理、设计师）汇报，提出改进建议。</span></li></ol><p id="uc83e80d1" class="ne-p"><br></p><p id="u7d38169e" class="ne-p"><br></p><h1 id="l12hS"><span class="ne-text">Evaluation Plan 模板</span></h1><div data-type="tips" class="ne-alert"><ul class="ne-ul"><li id="uae854320" data-lake-index-type="0"><span class="ne-text">记住四个关键词：Method - Participants - Tasks - Data</span></li></ul><ul class="ne-list-wrap"><ul ne-level="1" class="ne-ul"><li id="u03f703b7" data-lake-index-type="0"><span class="ne-text">Method：We use a small lab usability test</span></li><li id="u62c1f150" data-lake-index-type="0"><span class="ne-text">Participants：5-10participants；包含与 persona 对应的类型</span></li><li id="u522aca6b" data-lake-index-type="0"><span class="ne-text">Tasks：1-2 个典型任务</span></li><li id="uc673b94c" data-lake-index-type="0"><span class="ne-text">Data：</span></li></ul></ul><ul class="ne-list-wrap"><ul class="ne-list-wrap"><ul ne-level="2" class="ne-ul"><li id="ucd2a34eb" data-lake-index-type="0"><span class="ne-text">Quantitative：task completion time，success/failure，number of errors</span></li><li id="u19d70455" data-lake-index-type="0"><span class="ne-text">Qualitative：user comments，observed problems，satisfaction ratings</span></li></ul></ul></ul></div></details>

<details class="lake-collapse"><summary id="uf5a94c12"><span class="ne-text">伦理原则（ethical principles）</span></summary><p id="u7fd0662a" class="ne-p"><span class="ne-text"></span></p><p id="uefc0e817" class="ne-p"><strong><span class="ne-text">简约背诵版：</span></strong></p><ul class="ne-ul"><li id="udda11ac5" data-lake-index-type="0"><strong><span class="ne-text">Respect for User Autonomy：</span></strong><span class="ne-text">Informed Consent、Freedom of Choice &amp; Exit</span></li><li id="ub1f75e64" data-lake-index-type="0"><strong><span class="ne-text">Ensuring Safety &amp; Health：</span></strong><span class="ne-text">Physical Safety、Data Security</span></li><li id="u9d8119f9" data-lake-index-type="0"><strong><span class="ne-text">Fairness &amp; Inclusivity：</span></strong><span class="ne-text">Accessibility、Universal Design</span></li><li id="u86bfcace" data-lake-index-type="0"><strong><span class="ne-text">Transparency：</span></strong><span class="ne-text">Algorithm Explainability、Decision-making Disclosure</span></li><li id="u1039f3a2" data-lake-index-type="0"><strong><span class="ne-text">Social Responsibility：</span></strong><span class="ne-text">Environmental Sustainability、Social Harmony Promotion</span></li></ul><p id="uf5401782" class="ne-p"><br></p><p id="ucaa0f196" class="ne-p"><br></p><p id="udcf8b301" class="ne-p"><strong><span class="ne-text">详细理解版：</span></strong></p><p id="ub47a435d" class="ne-p"><br></p><p id="u23597e7f" class="ne-p"><span class="ne-text">尊重用户自主性</span></p><ul class="ne-ul"><li id="ufaa93f09" data-lake-index-type="0"><span class="ne-text">提供充分信息：确保用户在使用产品或服务前，能够获得足够且清晰的信息，包括功能特性、使用方法、潜在风险、隐私政策等。例如，在软件安装过程中，详细告知用户软件将获取的权限及其用途，让用户自主决定是否授予这些权限。</span></li><li id="u45902089" data-lake-index-type="0"><span class="ne-text">避免操纵行为：设计不应通过误导、欺骗或强迫等手段影响用户的决策。比如，一些不良的电商平台可能会使用限时抢购、虚假库存等手段诱导用户下单，这种行为就违背了尊重用户自主性的原则。</span></li><li id="uec5c9474" data-lake-index-type="0"><span class="ne-text">支持用户选择和退出：为用户提供多样化的选择，并允许他们随时更改或停止使用产品或服务。例如，在线订阅服务应提供方便的退订渠道，不能设置障碍阻止用户取消订阅。</span></li></ul><p id="u049af2fd" class="ne-p"><span class="ne-text">保障用户安全与健康</span></p><ul class="ne-ul"><li id="u2cc42eae" data-lake-index-type="0"><span class="ne-text">物理安全：对于涉及硬件产品的设计，要确保其在正常使用和可预见的异常情况下不会对用户造成身体伤害。比如，儿童玩具的设计要符合安全标准，避免存在尖锐边角、易吞咽的小零件等危险因素。</span></li><li id="ue0e5314e" data-lake-index-type="0"><span class="ne-text">心理和精神健康：设计不应导致用户出现焦虑、抑郁、成瘾等心理和精神问题。例如，社交媒体平台应避免过度推送引起用户负面情绪的内容，同时要采取措施防止用户沉迷，如设置使用时间提醒功能。</span></li><li id="u6a79fdf0" data-lake-index-type="0"><span class="ne-text">数据安全：保护用户的个人数据不被泄露、篡改或滥用。企业应采用先进的技术手段和严格的管理制度来保障数据安全，例如对用户数据进行加密存储，定期进行安全漏洞检测和修复。</span></li></ul><p id="u2ca3a610" class="ne-p"><span class="ne-text">确保公平与包容</span></p><ul class="ne-ul"><li id="u4ddb01e6" data-lake-index-type="0"><span class="ne-text">无歧视设计：产品和服务应面向所有用户，不因其种族、性别、年龄、残疾、宗教信仰等因素而存在歧视。例如，网站和应用程序应具备无障碍访问功能，方便残障人士使用；在招聘类软件的算法设计中，要避免因性别等因素对求职者进行不公平的筛选。</span></li><li id="udd2ea0c8" data-lake-index-type="0"><span class="ne-text">普及性和可及性：设计要考虑不同用户群体的需求和能力，确保产品和服务具有广泛的可及性。比如，公共交通工具的设计要考虑老年人和残疾人的使用需求，设置无障碍通道、扶手等设施；软件的界面设计应采用清晰易懂的图标和文字，方便不同文化水平的用户操作。</span></li></ul><p id="u1a93dfad" class="ne-p"><span class="ne-text">保持透明度</span></p><ul class="ne-ul"><li id="u1ae9bf4d" data-lake-index-type="0"><span class="ne-text">设计过程透明：在可能的情况下，向用户公开产品或服务的设计过程和决策依据。例如，一些开源软件项目会公开其代码和开发文档，让用户可以了解软件的实现原理和功能特性。</span></li><li id="u683b5992" data-lake-index-type="0"><span class="ne-text">算法透明：对于使用算法进行决策的系统，如推荐算法、信用评估算法等，要向用户解释算法的基本原理和影响因素。例如，电商平台应向用户说明商品推荐的依据，让用户了解为什么会看到某些推荐商品。</span></li></ul><p id="ubc89951e" class="ne-p"><span class="ne-text">承担社会责任</span></p><ul class="ne-ul"><li id="u0e175e11" data-lake-index-type="0"><span class="ne-text">环境可持续性：在设计过程中考虑产品或服务对环境的影响，尽量采用环保材料和节能技术，减少资源消耗和环境污染。例如，电子产品的设计应考虑可回收性和能源效率，鼓励用户进行环保使用。</span></li><li id="uff6566f4" data-lake-index-type="0"><span class="ne-text">促进社会和谐：设计应有助于促进社会的和谐与发展，避免引发社会矛盾和冲突。例如，媒体平台在传播信息时要客观公正，避免传播虚假信息和煽动性言论，维护社会稳定。</span></li></ul></details>
