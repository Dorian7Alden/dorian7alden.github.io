# 第 9 章 转移指令的原理


**转移指令**：可以修改 IP，或同时修改 CS 和 IP 的指令。<font style="color:#002;">概括地讲，转移指令就是可以控制CPU执行内存中某处代码的指令。</font>



<font style="color:#500;">8086CPU的</font>**<font style="color:#500;">转移行为</font>**<font style="color:#500;">有以下几类：</font>

+ <font style="color:#000;">段内转移：只修改IP</font>
+ 由于转移指令对IP的修改范围不同，段内转移又分为：
    - 短转移
    - 近转移
+ <font style="color:#000;">段间转移：同时修改CS和IP</font>

<font style="color:#000;"></font>

<font style="color:#200;">8086CPU的转移指令分为以</font><font style="color:#5c4e3f;">下</font><font style="color:#200;">几类：</font>

+ 无条件转移指令(如：jmp)
+ 条件转移指令 
+ 循环指令(如：loop) 
+ 过程 
+ 中断

## <font style="color:#000000;">9.1 操作符 offset</font>


操作符offset在汇编语言中是由编译器处理的符号，它的功能是取得标号的偏移地址。

```plain
assume cs:codesg 

codesg segment

start:
  mov ax,offset start		;相当于mov ax,0
  s:mov ax,offset s			;相当于mov ax,3

codesg ends 
end start
```

> `mov ax,offset s`相当于指令`mov ax,3`,因为s是代码段中的标号，它所标记的指令是代码段中的第二条指令，**第一条指令长度为3个字节**，则s的偏移地址为3。
>

## 9.2 jmp 指令


<font style="color:rgb(1,0,0);">jmp 为</font>**<font style="color:rgb(1,0,0);">无条件</font>**<font style="color:rgb(1,0,0);">转移指令，可以只修改IP，也可以同时修改 CS 和 IP。</font>

jmp 指令要给出两种信息：

1. 转移地目的地址
2. 转移的距离（段间转移、段内短转移、段内近转移）



## 9.3 依据位移进行转移的 jmp 指令


段内短转移：`jmp short 标号`（转到标号出执行指令）

+ <font style="color:#520;">它对 IP 的修改范围为 -128~127，也就是说，它向前转移时可以最多越过 128 个字节，向后转移可以最多越过 127 个字节。</font>
+ <font style="color:#520;">mp 指令中的“short”符号，说明指令进行的是短转移。</font>
+ <font style="color:#520;">转移指令结束后，CS:IP 应该指向标号处的指令</font>



:::info
在一般的汇编指令中，汇编指令中的 idata（立即数），不论它是表示一个数据还是内存单元的偏移地址，都会在对应的机器指令中出现，因为 CPU 执行的是机器指令，它必须要处理这些数据或地址。

:::

:::info
在“jmp short 符号”指令所对应的机器码中，并不包含转移的**目的地址**，而包含的是转移的**位移**。这个位移，是编译器根据汇编指令的“标号”**计算出来**的。

:::

具体的计算方法如下所示：

<img src="https://gitee.com/Dorian7Alden/pic-go/raw/master/typora/1761122239406-5bce7450-3bee-482f-ac13-31aac29643a5.png" width="507.3333333333333" title="" crop="0,0,1,1" id="u874dc62c" class="ne-image">

实际上，`jmp short 符号`的功能为：(IP)=(IP)+8 位位移

1. 8 位位移=标号处的地址-jmp 指令后的第一个字节的地址；
2. short 指明此处的位移为 8 位位移；
3. 8 位位移的范围位 -128~127，用补码表示（参考附注 2）；
4. 8 位位移由编译程序在编译时算出。



还有一种和`jmp short 标号`功能相近的指令格式，`jmp near ptr 标号`，它实现的是段内近转移。



# 第 10 章 CALL 和 RET 指令


+ call 和 ret 指令都是转移指令，它们都修改 IP，或同时修改 CS 和 IP。
+ 它们经常被共同用来实现子程序的设计。



## 10.1 ret 和 retf


+ ret 指令用栈中的数据，修改 IP 的内容，从而实现**近转移**；
+ retf 指令用栈中的数据，修改 CS 和 IP 的内容，从而实现**远转移**。



CPU 执行 ret 指令时，进行下面 2 步操作：

```z80
(IP) = ((SS) * 16 + (SP))
(SP) = (SP) + 2
```

CPU 执行 retf 指令时，进行下面 4 步操作：

```z80
(IP) = ((SS) * 16 + (SP))
(SP) = (SP) + 2
(CS) = ((SS) * 16 + (SP))
(SP) = (SP) + 2
```



:::info
可以看出，如果我们用汇编语法来解释 ret 和 retf 指令，则：

CPU 执行 ret 指令时，相当于进行：`pop IP`

CPU 执行 retf 指令时，相当于进行：`pop IP`	`pop CS`

:::



## 10.2 call 指令


CPU 执行 call 指令时，进行两步操作：

1. 将当前的 IP 或 CS 和 IP 压入栈中；
2. 转移。



call 指令不能实现短转移，除此之外，call 指令实现转移的方法和 jmp 指令的原理相同。



## 10.3 依据位移进行转移的 call 指令


`call 标号(将当前的IP压栈后，转到标号处执行指令)`

CPU 执行此种格式的 call 指令后，进行如下的操作：

```z80
(SP)=(SP)-2
((SS)*16+(SP))=(IP)
(IP)=(IP)+16位位移
```

+ 16 位位移=标号处的地址-call 指令后的第一个字节的地址
+ 16 位位移的范围为-32768~32767，用补码表示；
+ 16 位位移由编译程序在编译时算出。

:::info
用汇编语法来解释为：

push IP

jmp near ptr 标号

:::



## 10.4 转移的目的地址在指令中的 call 指令


call 指令，其对应的机器指令中并没有转移的目的地址，而是相对于当前 IP 的转移位移。



`call far ptr 标号`实现的是段间转移

CPU 执行此种格式的 call 指令时，进行如下的操作：

```z80
(SP)=(SP)-2
((SS)*16+(SP))=(CS)
(SP)=(SP)-2
((SS)*16+(SP))=(IP)
(CS)=标号所在段的段地址
(IP)=标号在段中的偏移地址
```

:::info
用汇编的语法来解释为：

push CS

push IP

jmp far ptr 标号

:::



## 10.5 转移地址在寄存器中的 call 指令


`call 16位reg`

```z80
(SP)=(SP)-2
((SS)*16+(SP))=(IP)
(IP)=(16位reg)
```

```z80
push IP
jmp 16位reg
```

# 第 11 章 标志寄存器


:::tips
**标志寄存器**：

1. 用来存储相关指令的某些执行结果；
2. 用来为 CPU 执行相关指令提供行为依据；
3. 用来控制 CPU 的相关工作方式。

:::

:::tips
8086CPU 的标志寄存器有 16 位，其中存储的信息通常被称为<u>程序状态字</u>（PSW）。（简称 flag）

:::

:::tips
flag 不是用来存放数据的。flag 寄存器是按位起作用的，每一位都有专门的含义，记录特定的信息。

:::

## 11.1 ZF 标志（Zero flag）


:::tips
**ZF**：零标志位。它记录相关指令执行后，其结果是否为 0。

:::

:::tips
如果结果为 0，那么 ZF=1；如果不为 0，那么 ZF=0。

:::

```z80
MOV	AX,1
SUB	AX,1
```

```z80
MOV	AX,2
SUB	AX,1
```

```z80
MOV	AX,1
AND	AX,0
```

```z80
MOV	AX,1
OR	AX,0
```

:::color5
大多<u>运算指令</u>会影响标志寄存器；大多<u>传送指令</u>不会影响标志寄存器。

:::



## 11.2 PF 标志（Parity flag）


:::tips
**PF**：奇偶标志位。相关指令执行后，其结果的所有 bit 位中 1 的个数是否为偶数。

:::



## 11.3 SF 标志（Sign flag）


:::tips
**SF**：符号标志位。**<u>有符号数</u>**运算结果时，记录数据的正负；当把数据作为无符号数运算时，SF 没有意义。

:::

:::tips
计算机中，通常用补码来表示有符号数据。一个数据可以看作是有符号数，也可以看成是无符号数。

:::



## 11.4 CF 标志（Carry flag）


:::tips
**CF**：进位标志位。在进行**<u>无符号数</u>**运算的时候，它记录了运算结果的<u>最高有效位</u>向<u>更高位</u>的进位值，或从更高位的借位值。

:::

```z80
MOV	AL,98H
ADD	AL,AL		;执行后，(AL)=30H，CF=1，CF记录了从最高有效位向更高位的进位值
ADD AL,AL		;执行后，(AL)=60H，CF=0
```

```z80
MOV	AL,97H
SUB	AL,98H		;执行后：(AL)=FFH，CF=1，CF记录了向更高位的借位值
SUB	AL,AL			;执行后：(AL)=0，CF=0
```



## 11.5 OF 标志（Overflow flag）


:::tips
**OF**：溢出标志位。记录了<u>有符号数</u>运算的结果是否发生了溢出。是，则为 1；否，则为 0。

:::

:::color5
注意 CF 跟 OF 的区别：前者是<u>无符号数</u>运算有意义的标志位，后者是<u>有符号数</u>运算有意义的标志位。

:::

:::color5
注意：有符号数解读规则是转为<u>补码</u>进行解读

:::

## 11.6 adc 指令


:::tips
定义：带进位加法指令，利用了 CF 位上记录的进位值。

:::

## 11.8 cmp 指令


:::tips
CMP 是比较指令，CPM 的功能相当于<u>减法</u>指令，只是不保存结果。CMP 指令执行后，<u>将对标志寄存器产生影响</u>。其他相关指令通过识别这些被影响的标志寄存器位来得知比较结果。

:::

:::tips
CMP	AX,BX												（有符号数运算）

如果 (AX)=(BX) 则 (AX)-(BX)=0，所以：ZF=1；

如果 (AX)≠(BX) 则 (AX)-(BX)≠0，所以：ZF=0；

如果 (AX)＜(BX) 则 (AX)-(BX)将产生借位，所以：CF=1；

如果 (AX)≥(BX) 则 (AX)-(BX)不必借位，所以：CF=0；

如果 (AX)＞(BX) 则 (AX)-(BX) 既不必借位，结果又不必为 0，所以：CF=0 并且 ZF=0；

如果 (AX)≤(BX) 则 (AX)-(BX) 既可能借位，结果可能为 0，所以：CF=1 或 ZF=1；

:::

:::tips
CMP	AX,BX												（无符号数运算）

ZF=1，说明(AX)=(BX)

ZF=0，说明(AX)≠(BX)

CF=1，说明(AX)＜(BX)

CF=0，说明(AX)≥(BX)

CF=0 并且 ZF=0，说明(AX)＞(BX)

CF=1 或 ZF=1，说明(AX)≤(BX)

:::

:::color5
CPU 在执行 CMP 指令的时候，也包含两种含义：<u>无符号数运算</u>和<u>有符号数运算</u>

# 第 12 章 内中断


:::tips
任何一个通用的 CPU，可以在执行完当前正在执行的指令之后，检测到从 CPU 外部发送过来的或内部产生的一种特殊信息，并且可以**立即**对所接收到的信息进行**处理**。这种特殊信息，称之为**中断消息**。

中断的意思是指，CPU 不再接着（刚执行完的指令）向下执行，而是转去处理这个特殊信息。

中断信息可以来自 CPU 的内部和外部，这一章中，主要讨论来自**内部**的中断信息。

:::



## 12.1 内中断的产生


:::tips
对于 8086CPU，当 CPU 内部有下面的情况发生的时候，将产生相应的中断信息：

1. 除法错误，比如，执行 div 指令产生的除法溢出；
2. 单步执行；
3. 执行 into 指令；
4. 执行 int 指令。

:::

:::tips
要进行不同的处理，CPU 首先要知道，所接收到的中断信息的来源。所以中断信息中必须包含识别来源的编码

:::

:::tips
8086CPU 用**中断类型码**来标识中断信息的来源。中断类型码为一个**字节型**数据，可以表示 256 种中断信息的来源。将产生中断信息的事件，即中断信息的来源，简称为**中断源**。

1. 除法错误：0
2. 单步执行：1
3. 执行 into 指令：4
4. 执行 int 指令，该指令的格式为 int n，指令中的 n 为字节型立即数，是提供给 CPU 的中断类型码。

:::

:::color5
有 0 号中断码！从 0 号开始

:::



## 12.2 中断处理程序


:::tips
用来处理中断信息的程序被称为中断处理程序。一般来说，需要对不同的中断信息编写不同的处理程序。

:::

:::tips
CPU 在收到中断信息后，应该转去执行该中断信息的处理程序。首要问题是：CPU 在收到中断信息后，如何根据中断信息确定其处理程序的入口。

:::

:::tips
CPU 的设计者必须在中断信息和其处理程序的入口地址之间建立某种联系，使得 CPU 根据中断信息可以找到要执行的处理程序。

:::

:::tips
中断信息中包含有标识中断源的类型码。根据 CPU 的设计，中断类型码的作用就是用来定位中断处理程序。若要定位中断处理程序，需要知道它的段地址和偏移地址，那么如何根据 8 位的中断类型码得到中断处理程序的段地址和偏移地址呢？

:::



## 12.3 中断向量表


:::tips
CPU 用 8 位的中断类型码通过**中断向量表**找到相应的中断处理程序的入口地址。

中断向量表：**中断向量**的列表。就是中断处理程序入口地址的列表。

中断向量：中断处理程序的额入口地址

:::

:::tips
中断向量表在**内存**中保存，其中存放着 256 个中断源所对应的中断处理程序的入口。如下图所示：

<img src="https://gitee.com/Dorian7Alden/pic-go/raw/master/typora/1764746980508-73eb2984-eac3-4b38-a537-84e8d23d900f.png" width="254" title="" crop="0,0,1,1" id="u4a0e4f34" class="ne-image">

因此，CPU 只要知道了中断类型码，就可以将中断类型码作为中断向量表的表项号，定位相应的表项，从而得到中断处理程序的入口地址。



现在，找到中断向量表成了通过中断类型码找到中断处理程序入口地址的先决条件。

:::

:::tips
中断向量表在**内存中**存放，对于 8086PC 机，中断向量表指定放在内存地址 0 处。从内存 0000:0000 到 0000:03FF 的 1024 个单元中存放着中断向量表。只能放在这个地址区间内，这是规定。

:::

:::tips
表项占用空间大小：一个表项存放一个中断向量，也就是一个中断处理程序的入口地址，对于 8086CPU，这个入口地址包括段地址和偏移地址，所以**一个表项占两个字**，高地址字存放段地址，低地址字存放偏移地址。

:::

## 12.4 中断过程


:::tips
用中断类型码找到中断向量，并用它设置 CS 和 IP，这个工作是由 CPU 的硬件自动完成的。CPU 硬件完成这个工作的过程被称为**中断过程**。

:::

:::tips
CPU 收到中断信息后，首先将引发中断过程。硬件在完成中断过程后，CS:IP 将指向中断处理程序的入口，CPU 开始执行中断处理程序。

:::

:::tips
在中断过程中，在设置 CS:IP 之前，还要将原来的 CS 和 IP 的值保存起来。跟 call 指令调用子程序时有同样的问题。

:::

:::tips
8086CPU 在收到中断信息后，所引发的中断过程：

1. （从中断信息中）取得中断类型码；
2. 标志寄存器的值入栈（因为在中断过程中要改变标志寄存器的值，所以先将其保存在栈中）；
3. 设置标志寄存器的第 8 位 TF 和第 9 位 IF 的值为 0；（原因在下一小节）
4. CS 的内容入栈；
5. IP 的内容入栈；
6. 从内存地址为中断类型码*4 和中断类型码*4+2 的两个字单元中读取中断处理程序的入口地址设置 IP 和 CS。

:::

:::tips
更简洁地描述中断过程：

1. 取得中断类型码 N；
2. pushf
3. TF=0, IF=0
4. push CS
5. push IP
6. (IP)=(N*4), (CS)=(N*4+2)

最后一步完成后，CPU 开始执行由程序员编写的中断处理程序。

:::

:::color5
IF 是**可屏蔽中断的控制开关**：

+ 当`IF=1`时，CPU 允许响应**可屏蔽中断请求**（比如外设的中断信号）；
+ 当`IF=0`时，CPU 禁止响应可屏蔽中断请求。

<font style="color:rgba(0, 0, 0, 0.85);">中断过程中把</font>`<font style="color:rgba(0, 0, 0, 0.85);">IF设为0</font>`<font style="color:rgba(0, 0, 0, 0.85);">，是为了</font>**避免当前中断处理被其他可屏蔽中断打断**<font style="color:rgba(0, 0, 0, 0.85);">：中断处理程序需要连续执行以完成任务，若不关闭 IF，新的可屏蔽中断会嵌套进来，可能导致处理逻辑混乱或栈溢出。</font>

<font style="color:rgba(0, 0, 0, 0.85);"></font>

TF 是**单步执行的控制开关**：

+ 当`TF=1`时，CPU 进入 “单步调试模式”—— 每执行**一条指令**，就自动触发一次 “单步中断”（用于调试程序，逐行观察指令执行效果）；
+ 当`TF=0`时，CPU 正常连续执行指令。

<font style="color:rgba(0, 0, 0, 0.85);">中断过程中把</font>`<font style="color:rgba(0, 0, 0, 0.85);">TF设为0</font>`<font style="color:rgba(0, 0, 0, 0.85);">，是为了</font>**保证中断处理程序能正常连续执行**<font style="color:rgba(0, 0, 0, 0.85);">：若 TF 保持为 1，中断处理程序的每一条指令都会触发单步中断，导致处理流程无法正常完成。</font>

:::



## 12.5 中断处理程序和 iret 指令


:::tips
由于 CPU 随时都可能检测到中断信息，也就是说，CPU 随时都可能执行中断处理程序，所以中断处理程序必须一直存储在内存某段空间之中。而中断处理程序的入口地址，即中断向量，必须存储在对应的中断向量表表项中。

:::

:::tips
中断处理程序的编写方法和子程序的比较相似，下面是常规的步骤：

1. 保存用到的寄存器；
2. 处理中断；
3. 恢复用到的寄存器；
4. 用 iret 指令返回。

:::

:::tips
iret 指令的功能用汇编语法描述为：

pop IP

pop CS

popf

:::

:::tips
iret 通常和硬件自动完成的中断过程配合使用。中断过程中，寄存器入栈的顺序是标志寄存器、CS、IP，而 iret 的出栈顺序是 IP、CS、标志寄存器，刚好和其相对应，实现了用执行中断处理程序前的 CPU 现场恢复标志寄存器和 CS、IP 的工作。iret 指令执行后，CPU 回到执行中断处理程序前的执行点继续执行程序。

:::

+ 之后，PC中内容自动“+1”，准备读取下一条指令。
+ 如果每取走一条指令，PC都只做简单的加1操作，则程序将会顺序执行
+ PC是程序执行的“指挥棒”。PC指向哪里，CPU就到哪里取指令

### 硬件系统


1. 

:::tips
微处理器（中央处理器，CPU）：

+ 运算器（算术逻辑运算单元 ALU。Arithmetic and Logic Unit）：对信息进行加工、处理及运算的逻辑部件，以加法器为基础。在控制信号的作用下可以完成四则运算和逻辑运算。
+ 控制器（Control Unit）：包括指令寄存器、指令译码器和定时控制电路。计算机控制和调度的中心。指挥是通过放在存储器中的程序进行的。整个 CPU 的指挥控制中心。
+ 寄存器组：由多个功能不同的寄存器构成，存放参加处理和运算的操作数，存放数据处理的中间结果和最终结果等。
    - 专用寄存器：固定作用。如：标志寄存器、程序计数器等
    - 通用寄存器。

:::



2. 

:::tips
存储器（半导体存储器）：存储和记忆装置。用来存储数据、程序、中间结果和最终结果等数据信息。

内部存储器：主存储器，简称内存或主存。系统主板上。存储速度快，容量小。

+ RAM（随机读写存储器）（Random Access Memory）：存放数据。断电后，信息消失。
+ ROM（只读存储器）（Random Only Memory）：存固定程序，BIOS。断电后，保留。

外部存储器：辅助存储器，简称辅存。存暂时不用的程序、数据等。CPU 只能执行内存的信息。

:::

:::tips
**存储器管理的主要功能：**

+ 负责将程序从联机外存储器（硬盘）调入内存（将数据从外存装入到内存）
+ 将硬盘和内存实行统一管理，以扩大存储容量（解决在小的存储空间中运行大程序的问题）
+ 保护各类程序及数据区免遭破坏（存储保护）

:::

:::tips
存储分配与地址变换：由于编译器不能预知目标程序在内存中的位置，故每个目标程序的逻辑地址都从 0 开始。

地址重定位：将程序逻辑地址变换为要装入的内存物理地址的过程。静态、动态重定位。现代计算机系统采用动态重定位。

:::



:::tips
虚拟存储技术：

+ 将内存与部分硬磁盘统一管理，使其构成一个整体，从而将部分外存空间作为内存使用。
+ 相当于有一个容量足够大的内存空间。用户可以在这个地址空间内编程，而完全不考虑内存的大小。（实现存储扩充）

:::



:::tips
软硬件协同：

+ 每条指令的执行都依靠一个物理电路的支持。指令和物理电路之间的对应，是计算机硬件和软件之间最基本的连接关系，也是软、硬件协同工作的基础。
+ 计算机系统中的其它硬件设备也有类似的对应关系，如每一种连接到处理器的设备都有对应的接口卡（硬件）和相应的设备驱动程序（软件）。
+ 计算机开机后最先执行的程序是操作系统，操作系统启动后再反过来开始管理CPU和各种硬件设备和文件，并响应各种应用程序发出的请求

:::



3. 

:::tips
输入/输出接口：

+ 输入设备（Input Device）和输出设备（Output Device），二者合称为外部设备，简称I/O设备。
+ 常用的输入设备有键盘、鼠标、扫描仪、模/数转换器等。
+ 常用输出设备有打印机、绘图仪、显示器、数/模转换器等。
+ 磁盘，既是输入也是输出

:::

:::tips
**输入输出接口（I/O Interface）：**

微机的CPU要与多个外部设备进行数据交换和信息传递，但是CPU不能直接与外部设备相连接。

CPU与外部设备之间的中间控制电路被称为输入输出接口电路，简称**I/O接口电路**，又称为**I/O适配器**。

CPU**必须**通过“I/O接口”才能与外部设备交换数据，所以输入输出接口是CPU与外设之间信息传送的桥梁。

:::



4. 

:::tips
总线（BUS）（元件级总线）：

总线就是把多个功能部件连接起来，用于各功能部件之间的信息传递和数据交换的一组公共通信线路。

在CPU、存储器、I/O接口之间传输信息的公共通信线路称为系统总线。

系统总线分为3类：地址总线、数据总线、控制总线

+ 地址总线：**单向**输出，三态控制，简称AB（Address Bus）。地址总线的宽度决定了内部存储器最大的存储容量。8位计算机：地址总线16位    内存216B=65535B    64KB   0000H～FFFFH空间
+ 数据总线：**双向**，三态控制，简称DB（Data Bus），用于CPU与存储器和I/O接口之间的传输数据信息。8位计算机：数据总线8位   D0 ～D7。8086计算机：数据总线16位   D0 ～D15
+ 控制总线：三态控制，简称CB（Control Bus），用于传送各种控制命令信号、时序信号和状态信号。控制总线中每一根线都有固定的作用和方向

:::



### 软件


:::tips
操作系统基本功能：

<img src="https://gitee.com/Dorian7Alden/pic-go/raw/master/typora/1764897469564-09a7dea3-3c92-4376-8fdd-a436d803c357.png" width="487.3333333333333" title="" crop="0,0,1,1" id="u0bc19499" class="ne-image">

顺序执行方式：特点：按顺序执行、资源独享、结果可再现

程序的并发执行：

+ 并发执行方式特点：
+ 多道程序共享系统资源，程序间相互制约，呈间断性；
+ 程序执行结果易受其它程序的影响（系统资源的状态由多道程序改变），失去封闭性；
+ 程序每次执行结果可能不相同，呈现不可再现性。

:::



:::tips
冯•诺依曼结构的局限性：

+ CPU与存储器只间会有大量的数据交互，造成总线瓶径；
+ 指令的执行顺序由PC控制，使得既使有关数据巳经准备好，也必须逐条执行指令序列。
+ 指令的执行顺序由程序决定，对大型、复杂的任务比较困难；
+ 以运算器为中心，I/O设备与存储器间的数据传送都要经过运算器，使处理效率、特别是对非数值数据的处理效率比较低。

:::

:::tips
**<font style="color:rgb(31, 35, 41);background-color:rgba(0, 0, 0, 0);">地址总线（Address Bus）</font>**<font style="color:rgb(31, 35, 41);background-color:rgba(0, 0, 0, 0);">：用于</font>_<font style="color:rgb(31, 35, 41);background-color:rgba(0, 0, 0, 0);">单向传输 CPU 要访问的内存单元或地址信息</font>_<font style="color:rgb(31, 35, 41);background-color:rgba(0, 0, 0, 0);">。地址总线的位数决定了系统的最大寻址能力。</font>

**<font style="color:rgb(31, 35, 41);background-color:rgba(0, 0, 0, 0);">数据总线（Data Bus）</font>**<font style="color:rgb(31, 35, 41);background-color:rgba(0, 0, 0, 0);">：用于</font>_<font style="color:rgb(31, 35, 41);background-color:rgba(0, 0, 0, 0);">传输 CPU 与内存、I/O 设备之间的双向数据</font>_<font style="color:rgb(31, 35, 41);background-color:rgba(0, 0, 0, 0);">。数据总线的宽度（位数）决定了单次数据传输的最大位数，直接影响数据传输速率。</font>

**<font style="color:rgb(31, 35, 41);background-color:rgba(0, 0, 0, 0);">控制总线（Control Bus）</font>**<font style="color:rgb(31, 35, 41);background-color:rgba(0, 0, 0, 0);">：用于传输控制信号、时序信号和状态信号，</font>_<font style="color:rgb(31, 35, 41);background-color:rgba(0, 0, 0, 0);">协调系统中各个部件的操作</font>_<font style="color:rgb(31, 35, 41);background-color:rgba(0, 0, 0, 0);">。控制总线的信号类型决定了系统的控制能力，其传输方向根据信号类型可单向或双向。</font>

:::



:::tips
<font style="color:rgb(31, 35, 41);background-color:rgba(0, 0, 0, 0);">主要是解决</font>**<font style="color:rgb(31, 35, 41);background-color:rgba(0, 0, 0, 0);">CPU 与内存的速度不匹配问题</font>**<font style="color:rgb(31, 35, 41);background-color:rgba(0, 0, 0, 0);">：</font>

1. <font style="color:rgb(31, 35, 41);background-color:rgba(0, 0, 0, 0);">速度瓶颈：CPU 的运算速度远高于内存的</font>**<font style="color:rgb(31, 35, 41);background-color:rgba(0, 0, 0, 0);">读写速度</font>**<font style="color:rgb(31, 35, 41);background-color:rgba(0, 0, 0, 0);">，若 CPU 直接访问内存，会频繁处于等待内存数据的状态，大幅降低系统整体性能。</font>
2. <font style="color:rgb(31, 35, 41);background-color:rgba(0, 0, 0, 0);">效率优化：cache 是一种速度接近 CPU 的高速存储部件，可存放 CPU 近期</font>**<font style="color:rgb(31, 35, 41);background-color:rgba(0, 0, 0, 0);">高频访问</font>**<font style="color:rgb(31, 35, 41);background-color:rgba(0, 0, 0, 0);">的数据 / 指令，减少 CPU 与内存的交互延迟，提升数据访问效率。</font>

过程原理：

1. **<font style="color:rgb(31, 35, 41);background-color:rgba(0, 0, 0, 0);">缓存命中</font>**<font style="color:rgb(31, 35, 41);background-color:rgba(0, 0, 0, 0);">：CPU 访问数据 / 指令时，先查询 cache；若目标内容已在 cache 中，则直接从 cache 读取，完成快速访问。</font>
2. **<font style="color:rgb(31, 35, 41);background-color:rgba(0, 0, 0, 0);">缓存不命中</font>**<font style="color:rgb(31, 35, 41);background-color:rgba(0, 0, 0, 0);">：若 cache 中无目标内容，先从内存读取该内容，同时将该内容所在的 “数据块”（包含相邻地址的内容）载入 cache，以便后续同类访问直接命中。</font>
3. **<font style="color:rgb(31, 35, 41);background-color:rgba(0, 0, 0, 0);">缓存替换</font>**<font style="color:rgb(31, 35, 41);background-color:rgba(0, 0, 0, 0);">：当 cache 空间不足时，通过替换算法（如 “最近最少使用（LRU）”），替换掉 cache 中近期使用频率较低的块，保证 cache 中始终存放高频访问的内容。</font>

:::

| 对比维度 | 宏指令（Macro） | 子程序（Subroutine） |
| :---: | --- | --- |
| 定义与本质 | 是汇编阶段由宏汇编器处理的**代码片段模板**，本质是“代码替换规则” | 是内存中独立存放的**可重复执行的代码块**，本质是“独立的功能模块” |
| **执行机制** | 汇编时直接将宏体代码**插入**调用处（无跳转/返回操作） | 运行时通过`CALL`指令**跳转**到子程序地址执行，执行完通过`RET`返回调用处 |
| **代码空间占用** | 每次调用都会展开宏体，多次调用会**重复占用**代码段空间 | 仅在内存中存储一份代码，多次调用**共享同一份空间**，更节省内存 |
| **参数传递方式** | 支持直接的“形参-实参替换”，可传递常量、寄存器、内存单元等，**灵活简单** | 需通过寄存器、栈、全局内存单元传递参数，**流程相对繁琐** |
| **执行效率** | 无跳转/返回的指令开销，**执行速度快** | 存在`CALL`/`RET`的跳转开销，**执行效率略低** |
| **适用场景** | 适合**代码短小、调用次数少**的功能（如简单运算、寄存器赋值） | 适合**功能独立、调用次数多**的复杂逻辑（如数据处理、I/O操作） |
