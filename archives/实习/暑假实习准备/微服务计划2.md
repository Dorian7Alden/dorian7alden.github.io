## 一、 系统架构与微服务拆分清单

- [ ] **设计与规划微服务边界**
  - **目标**：将 LeetModel 的业务模块划分为独立的微服务，明确各服务职责。
  - **交付物**：微服务架构图、业务模块与服务映射表。
- [ ] **搭建 API 网关与统一入口**
  - **目标**：建立系统统一入口，实现路由转发、请求鉴权与全局限流。
  - **交付物**：可运行的网关服务，统一处理客户端请求。
- [ ] **配置服务注册与集中化配置中心**
  - **目标**：实现服务间的动态发现与配置统一管理。
  - **交付物**：服务节点可自动注册与发现，配置变更可动态生效。
- [ ] **建立服务间通信机制**
  - **目标**：完成服务间的同步与异步调用设计。
  - **交付物**：同步 RPC/HTTP 接口定义，异步消息传递契约。

## 二、 核心业务功能开发清单

### 1. 代码/数据判题与安全沙箱服务

- [ ] **实现异步判题调度**
  - **目标**：接收用户提交的代码与数据集，解耦判题请求与响应。
  - **交付物**：判题任务队列，支持长耗时任务处理。
- [ ] **构建安全运行沙箱**
  - **目标**：在隔离环境中运行用户提交的代码（如 Python/MATLAB/R），防范恶意代码与超限资源占用。
  - **交付物**：具备 CPU、内存、网络与运行时间限制的隔离运行环境。
- [ ] **建立判题结果与日志实时回显**
  - **目标**：将判题进度与运行日志实时推送至前端。
  - **交付物**：长连接/流式数据传输通道。

### 2. AI 论文与逻辑评审服务

- [ ] **设计 AI 评审工作流状态机**
  - **目标**：将建模论文（PDF/Markdown）与代码的评审过程拆解为多阶段工作流。
  - **交付物**：包含静态校验、模型合理性评估、一致性比对等多节点可恢复的评审流程。
- [ ] **构建大模型调用保障机制**
  - **目标**：应对大模型接口超时、失败与高成本问题。
  - **交付物**：包含重试策略、熔断降级机制与调用限流方案。
- [ ] **搭建建模领域知识检索增强（RAG）**
  - **目标**：引入外部建模优秀论文与算法知识库，提升评审准确度。
  - **交付物**：知识库向量化存储与混合检索模块。

### 3. 题目、社区与实时排行榜服务

- [ ] **设计实时多维排行榜**
  - **目标**：支持高并发下的提交分数、耗时等多维度实时排名。
  - **交付物**：高效排行榜数据接口。
- [ ] **高并发读写与数据一致性设计**
  - **目标**：保障题目详情、解题思路等高频读取数据的性能与最终一致性。
  - **交付物**：数据缓存方案与一致性保障机制。

## 三、 工程化基建与质量保障清单

- [ ] **实现全局异常与统一响应规范**
  - **目标**：标准化全系统接口返回格式与错误码体系。
  - **交付物**：统一响应结构体与全局异常拦截器。
- [ ] **落地全链路日志追踪（Trace ID）**
  - **目标**：使跨微服务的请求可以通过唯一 Trace ID 进行全链路日志串联。
  - **交付物**：日志输出中包含可追溯的链路标识。
- [ ] **编写单元测试与集成测试**
  - **目标**：为判题、评审等核心逻辑建立自动化测试。
  - **交付物**：核心代码单元测试覆盖率达标。
- [ ] **开展性能压测与排障演练**
  - **目标**：定位系统高并发下的吞吐瓶颈，演练常见线上故障排查。
  - **交付物**：JMeter 压测报告，高 CPU/内存溢出排障记录。

## 四、 自动化部署与 DevOps 清单

- [ ] **实现微服务容器化**
  - **目标**：为所有微服务及依赖组件编写容器构建脚本。
  - **交付物**：轻量化 Docker 镜像及本地编排启动配置文件。
- [ ] **搭建 CI/CD 自动化流水线**
  - **目标**：实现代码提交后自动执行构建、测试与部署。
  - **交付物**：运行成功的自动化构建与部署 Pipeline。
- [ ] **管理多环境配置**
  - **目标**：实现开发、测试、生产环境的配置隔离与敏感信息脱敏。
  - **交付物**：隔离的环境配置文件及环境变量加载机制。
